# Controlled Output and Publication Standard

## Objective
Every client, professional, commercial and statutory-facing output must be traceable to a governed project snapshot and an approved template version.

## Controlled generation chain
1. Select the intended output and purpose.
2. Resolve the active approved template and required data paths.
3. Freeze a project report snapshot containing source hashes and references.
4. Validate required facts, requirements, regulatory state, commercial data and release conditions.
5. Generate the artifact in the requested controlled format.
6. Record input hash, output checksum, template version and source snapshot.
7. Review and approve according to resource criticality and purpose.
8. Issue only when zero unresolved critical defects remain.

## Non-negotiable controls
- Draft or unlocked templates may not generate issued artifacts.
- Generated outputs may not invent unavailable project information. Missing information is shown as Not Verified / Not Available.
- A human-edited controlled artifact becomes a new revision and must retain provenance.
- Public content and marketing claims require approval before publication.
- Legal, financial, regulatory and engineering statements cannot be silently rewritten by generative AI.
- Superseded and withdrawn artifacts remain immutable in the audit history.

## Publication sets
Publication sets group controlled artifacts for information, review, approval, tender, construction, record or handover. Each set carries a number, revision, approval state, issue authority and item sequence.

## Brand integrity
Output rendering uses an approved brand profile. Brand assets, typography direction, colours and legal footer data are configuration-controlled and cannot be substituted by an autonomous agent without approval.
