# Concept Spaces Engineering Verification & Validation Standard

Engineering outputs are not trusted because they are generated by software or AI.

## Engine eligibility

Every deterministic, parametric, optimisation or physics engine used for engineering work must have:
- stable engine identity and semantic version
- supported discipline, units and standards
- benchmark suite with expected references and declared tolerances
- reproducible execution evidence
- controlled certification state
- a maximum permitted project criticality
- checksum/build identity where available

## Calculation provenance

Every engineering calculation run must retain:
- exact engine ID and version
- immutable input snapshot reference and hash
- assumptions and unit system
- standard references
- output reference and hash
- execution timestamps
- evidence references

## Professional review

A review is bound to the exact resource hash. If the resource changes after review, the prior approval is no longer sufficient for the changed resource.

C3/C4 engineering deliverables cannot be issued solely because an automated calculation passed. Credential-eligible professional review remains a required release control.

## Failure behavior

If engine certification, input truth, assumptions, units, benchmark evidence or professional authority is insufficient, Concept Spaces must represent the result as NOT VERIFIED or blocked rather than infer trust.
